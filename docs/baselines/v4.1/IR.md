# DVEntityLinking V4.1 需求分析文档

最后更新：2026-07-16  
状态：草案，作为 V4.1 独立归一跟踪基线  
上游基线：[V4 IR](../v4/IR.md)、[V4 SR](../v4/SR.md)

## 1. 版本定位

V4.1 是 V4 验收收口后的兼容性解耦版本，不新增实体链接业务能力。其目标是在**不改变 V4 已验收功能、公开契约和结果语义**的前提下，消除 V4 对 V0–V3 历史实现、运行资产和测试基础设施的运行时依赖，并提供可审计、可验证的迁移路径。

V4.1 的完成不以“目录移动”或“测试仍然通过”为唯一证据；必须同时证明：生产链路不再进入 legacy，V4 行为与历史基线兼容，且每一项数据、配置和调用方迁移均可追踪。

## 2. 目标、范围与非目标

### 2.1 目标

| 目标 ID | 目标 | 可验收结果 |
| --- | --- | --- |
| IR-V4.1-001 | 运行时解耦 | 默认 V4.1 module、公开工厂与生产 Web/API adapter 不导入或实例化 `legacy/`、V3 Mock、Redis/Gauss JSON 或历史 demo 运行资产。 |
| IR-V4.1-002 | 公开兼容 | V4 已公开的请求、响应、状态、错误与安全 trace 语义保持兼容；新增信息只允许追加且带默认值。 |
| IR-V4.1-003 | 数据与配置迁移 | V4 可用实体数据、配置和部署参数具备明确的 V4.1 目标格式、迁移步骤、校验与失败处置。 |
| IR-V4.1-004 | 行为等价 | V1–V4 累计 golden case 与 V4 端到端用例在 V4.1 实现上保持预期结论；差异必须显式登记、评审并批准。 |
| IR-V4.1-005 | 可追踪交付 | 建立需求—设计—实现—测试—迁移证据的 ID 映射，支持后续版本归一跟踪。 |

### 2.2 范围内

- 建立独立的 V4.1 领域实现与装配边界，替代 V4 仍可能经过的历史实现路径。
- 识别并替换代码、依赖注入、配置、脚本、数据样例和测试中的历史运行依赖。
- 维持 V4 的 Entity Data IR、canonical entity schema、实体词匹配、候选确认与状态聚合语义。
- 提供数据、配置及调用方的迁移清单、校验机制、灰度/回退策略和兼容性对照测试。
- 将历史实现保留为只读回归资产或明确弃用资产，且不进入 V4.1 默认运行链。

### 2.3 非目标

- 不新增实体类型、匹配算法、LLM 阶段、数据库产品或对外业务接口。
- 不改变 V4 的单值实体词约束、fail-closed 原则、LLM 可选回退和安全投影规则。
- 不要求在 V4.1 内删除 V0–V4 历史文档、release 记录或测试证据。
- 不以双写、长期双读或永久兼容分支替代一次性、可验证的迁移；如确有必要，必须限定期限并登记退出条件。

## 3. 解耦边界

| 边界 | V4.1 目标状态 | 禁止状态 |
| --- | --- | --- |
| 领域与应用层 | V4.1 自有 `application/domain` 实现承载意图、识别、候选、选择和聚合。 | 公开入口或默认 pipeline 直接调用 `legacy` 私有函数。 |
| 数据访问 | 仅经版本化 `EntityDataClient` / Entity Data IR 读取实体词和实体详情。 | 默认回退 Redis、Gauss Mock、本地 JSON 或内存长期词表。 |
| 宿主集成 | 公开 DTO、门面和配置独立稳定；adapter 只依赖公开入口。 | 宿主导入 `legacy` 模型、存储对象或 Web 全局变量。 |
| 配置 | V4.1 配置有版本、默认值、校验及弃用说明。 | 通过未文档化环境变量或 V3 Mock 路径决定生产行为。 |
| 测试 | 历史用例作为外部 oracle；V4.1 有独立契约和迁移测试。 | 用 production trace 或同一实现同时生成输入与期望。 |

## 4. 兼容性契约

### 4.1 公开契约

V4.1 继续支持 V4 的公开 module 入口、同步/异步调用方式以及既有 Query 与 mention 级状态：`linked`、`partial`、`ambiguous`、`no_match`、`not_required`、`dependency_failed`、`invalid_input`。已有字段不得改名、删除或改变语义；新增字段必须可选并提供默认值。

V4.1 不承诺兼容历史内部模块、Mock 类、未公开脚本参数或直接访问数据结构的调用方式。需要保留的兼容入口必须在迁移清单中以 `CMP-V4.1-*` 编号明确列出、标注使用方和退出日期。

### 4.2 行为兼容

| 能力 | V4.1 必须保持的行为 |
| --- | --- |
| 已知词识别 | 归一化、span 还原、词边界、上下文确认、最长非重叠及重复出现的语义保持一致。 |
| 未知识别 | 数据服务空命中不阻断本地规则/可选抽取支路，未知 mention 与 no-match 原因可观察。 |
| 候选与状态 | 候选排序、歧义 fail-closed、`partial` 聚合和详情读取时序保持 V4 契约。 |
| LLM | S3/S5 仍是可选增强；关闭、低置信、异常或非法 schema 时按 V4 规则回退。 |
| 数据失败 | 超时、鉴权、坏 schema、版本不一致和详情缺失不得伪装为 `no_match`。 |
| 安全 | 不向响应、日志或 trace 暴露 IR URL、凭据、原始上游响应或敏感实体属性。 |

## 5. 迁移要求

### 5.1 迁移阶段

| 阶段 | 输出 | 准入条件 | 退出条件 |
| --- | --- | --- | --- |
| M1 盘点 | `MIG-V4.1-001` 依赖与调用方清单 | V4 验收基线冻结。 | 所有 legacy、配置、数据、脚本与外部调用点已分类。 |
| M2 目标实现 | 独立 V4.1 组件与装配 | 公开兼容矩阵已批准。 | 默认路径不含历史运行依赖。 |
| M3 数据/配置迁移 | 版本化迁移器、校验报告 | 目标 schema/配置已定义。 | 迁移可重复执行；校验通过或差异已批准。 |
| M4 对照验证 | 双实现或黄金结果对照报告 | M2、M3 完成。 | 关键用例等价；差异全部处置。 |
| M5 切换与收口 | 灰度/回退记录、弃用清单 | 回退路径已演练。 | 默认部署切至 V4.1，历史运行入口已禁用。 |

### 5.2 迁移原则

1. 迁移先读后写、先验证后切换；任何不可逆动作必须在执行前形成备份或可恢复证据。
2. 数据迁移以 canonical entity schema 和 Entity Data IR 契约为唯一目标，不保留静默字段双读。
3. 需要短期兼容适配时，适配器必须位于明确的边界层，记录 owner、到期版本和删除条件。
4. 切换失败可回退到已确认的 V4 部署版本；回退不能依赖未验证的数据反向转换。
